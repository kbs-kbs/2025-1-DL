## 토큰화
- 토큰화 결과는 리스트로 반환
```
# 단어 빈도수 세기

# 전처리하려는 세 개의 문장을 정합니다.
docs = ['먼저 텍스트의 각 단어를 나누어 토큰화합니다.',
       '텍스트의 단어로 토큰화해야 딥러닝에서 인식됩니다.',
       '토큰화한 결과는 딥러닝에서 사용할 수 있습니다.',
       ]
 
# 토큰화 함수를 이용해 전처리 하는 과정입니다.
token = Tokenizer()            # 토큰화 함수 지정
token.fit_on_texts(docs)       # 토큰화 함수에 문장 적용
 
# 단어의 빈도수를 계산한 결과를 각 옵션에 맞추어 출력합니다.
# Tokenizer()의 word_counts 함수는 순서를 기억하는 OrderedDict 클래스를 사용합니다.
print("\n단어 카운트:\n", token.word_counts) 

# 출력되는 순서는 랜덤입니다. 
print("\n문장 카운트: ", token.document_count)
print("\n각 단어가 몇 개의 문장에 포함되어 있는가:\n", token.word_docs)
print("\n각 단어에 매겨진 인덱스 값:\n",  token.word_index)
```

## 보강 — 5주차 딥러닝을 이용한 자연어 처리 파트2

> 교재 17장 3~4절(단어 임베딩, 감정 예측)과 `자연어처리_개념이해_Ver2.0` 교안을 함께 정리했습니다. 위의 토큰화·원핫 인코딩에 이어지는 부분입니다.

### 1. 벡터화 방법 세 가지 차이 (수업에서 짚은 부분)

| 방법 | 기준 | 특징 |
|---|---|---|
| `CountVectorizer` | 단어의 **등장 횟수** | 토크나이징 + 벡터화를 동시에. 빈도만 세므로 순서·문맥 정보는 없음 |
| `TfidfVectorizer` | **TF-IDF 값** | 문서에 많이 나오지만 여러 문서에 흔한 단어(a, the)의 가중치는 낮춤 |
| `HashingVectorizer` | 해시 함수 | CountVectorizer와 방법은 같지만 해시를 써서 **실행 시간이 짧고 메모리를 적게** 씀(단어 사전을 저장하지 않음) |

- TF = 문서 내 특정 단어의 출현 빈도, DF = 그 단어가 나타난 **문서 수**, IDF = DF의 역수에 로그를 취한 값
- 분모가 0이 되는 것을 막기 위해 1을 더하는 것을 **스무딩(smoothing)** 이라고 한다.
- TF-IDF는 키워드 검색 엔진, 중요 키워드 분석, 검색 결과 순위 결정에 쓰인다.

### 2. 단어 임베딩(word embedding)

- 원-핫 인코딩은 단어가 1만 개면 `[0, 0, ..., 1, ..., 0]`(9,999개의 0 + 1개의 1)을 1만 개나 만들어야 해서 **공간 낭비**가 크다.
- 임베딩은 이 배열을 **정해진 길이로 압축**한다(예: 16차원 → 4차원).
- 단어 간 **유사도**를 계산해 비슷한 단어는 비슷한 벡터가 되도록 학습한다(happy는 bad보다 good에 가깝다, cat은 good보다 dog에 가깝다).
- 이 유사도를 계산하는 데에도 **오차 역전파**가 쓰인다. 케라스에서는 `Embedding()` 한 줄로 처리된다.

```python
Embedding(16, 4)               # 입력될 총 단어 수 16, 임베딩 후 벡터 크기 4
Embedding(16, 4, input_length=2)  # 총 16개 단어지만 매번 2개씩만 넣겠다
```

### 3. 패딩(padding)

- 리뷰마다 토큰 수가 다르므로(‘최고예요’는 1개, ‘참 잘 만든 영화예요’는 4개) **길이를 같게** 맞춰야 한다.
- `pad_sequences(x, 4)` → 짧으면 0을 채우고, 길면 잘라서 4개로 맞춤.

### 4. 영화 리뷰 긍정/부정 예측 실습

```python
# ① 리뷰와 레이블(긍정 1, 부정 0)
texts = ['이 영화는 최고예요', '정말 재미없었어요', ...]
labels = [1, 0, ...]

# ② 토큰화
token = Tokenizer()
token.fit_on_texts(texts)

# ③ 인덱스 배열로 변환 → ④ 길이 맞추기(패딩)
x = token.texts_to_sequences(texts)
x = pad_sequences(x, 4)

# ⑤ 임베딩 파라미터 정하기
word_size = len(token.word_index) + 1   # 0번 자리 때문에 +1

# ⑥ 모델 만들기
model = Sequential()
model.add(Embedding(word_size, 8, input_length=4))
model.add(Flatten())
model.add(Dense(1, activation='sigmoid'))

model.compile(loss='binary_crossentropy', optimizer='adam', metrics=['accuracy'])
model.fit(x, labels, epochs=20)
```

- 임베딩의 세 파라미터 = ‘입력(총 단어 수), 출력(임베딩 결과 차원), 단어 수(매번 입력될 개수)’
- 출력 차원 8은 임의로 정한 값이며, 임베딩 결과는 눈에 보이지 않고 내부에서 계산되어 층으로 쓰인다.

### 5. 임베딩 네 계열 (개념 교안)

| 계열 | 대표 | 설명 |
|---|---|---|
| 희소 표현 | 원-핫 인코딩 | 대부분 0. 단어끼리 내적이 0(직교)이라 **유사도를 표현하지 못하고** 차원의 저주가 있음 |
| 횟수 기반 | 카운터 벡터, TF-IDF | 출현 빈도를 고려 |
| 예측 기반 | Word2Vec(CBOW·skip-gram), FastText | 문맥에서 다음/주변 단어를 예측하며 학습. FastText는 n-그램으로 **사전에 없는 단어**도 벡터화 |
| 횟수/예측 기반 | GloVe | 동시 발생 확률(전역 통계) + 예측 |

- **CBOW**: 주변 단어들로 가운데 단어를 예측 / **skip-gram**: 가운데 단어로 주변 단어를 예측
- 어느 쪽이 더 좋다고 단정하지 않고, 데이터 성격과 목적에 따라 고른다.

### 6. 한국어 처리

- 한국어는 띄어쓰기만으로 토큰을 나누기 어려워 **형태소 분석기(KoNLPy)** 를 쓴다. KoNLPy는 꼬꼬마·코모란·한나눔·트위터(Okt)·메캅을 한 번에 설치하고 같은 방법으로 쓸 수 있게 해 준다.
- **Gensim**: Word2Vec 라이브러리(임베딩, 토픽 모델링, LDA).
- **NLTK**: 교육용 자연어 처리 라이브러리(말뭉치, 토큰 생성, 형태소 분석, 품사 태깅).
